# ProxyBridge 全项目稳健审查与修复设计

## 目标

对 ProxyBridge 的 Python 后端、Web 前端、macOS 菜单栏程序和构建脚本进行一次证据驱动的全项目审查，修复可复现的缺陷、安全或并发问题，以及能够明确证明的代码冗余，同时保持现有产品行为和项目结构稳定。

## 范围与约束

- 覆盖 `app.py`、`static/`、`macos/ProxyBridgeMenuBar/`、`scripts/`、现有测试和相关文档。
- 每个行为修复必须由失败测试、稳定复现步骤、编译错误或明确静态证据支持。
- 采用最小修复；不进行大型文件拆分、框架迁移、界面重做或无关格式化。
- 仅删除确认未使用、重复、不可达或被等价实现完全覆盖的代码。
- 保留现有公开接口、状态文件结构、代理地址格式和用户可见工作流，除非它们本身构成已证实的缺陷。
- 不依赖真实订阅凭据，不把用户本地运行数据或生成物纳入提交。

## 审查结构

审查按四个相对独立的责任域执行，再进行跨模块接口核对：

1. **Python 后端与代理运行时**：输入解析、配置生成、状态持久化、线程共享状态、套接字转发、子进程与浏览器生命周期、下载和归档解压。
2. **Web 前端**：API 调用、HTML 转义、事件分发、筛选与状态渲染、异步操作的错误处理和重复逻辑。
3. **macOS 菜单栏程序**：进程启动与停止、运行时下载、路径与架构处理、HTTP 通信、生命周期清理和 Swift 类型安全。
4. **构建与资源脚本**：引用路径、错误传播、临时文件、产物完整性、环境变量处理和重复步骤。

跨模块核对以后端 API 路由及 JSON 字段为中心，确认 JavaScript 和 Swift 消费端与后端生产端一致。

## 工作流

1. 运行当前 Python 测试、Python/JavaScript/Shell 语法检查和可用的 Swift 编译检查，记录未修改前的基线。
2. 对四个责任域并行进行静态审查，并将发现按严重性、证据和影响范围归类。
3. 对疑似行为缺陷先补充最小失败测试或可重复检查，确认测试因目标缺陷失败。
4. 实施最小代码修改，使新增测试通过，并运行相关回归测试。
5. 对没有合适自动化测试入口的 Swift、Shell 或界面问题，使用编译、语法检查、接口契约核对或确定性的静态检查验证。
6. 合并各责任域结果后运行全量验证，并由独立审查者检查遗漏、回归风险和不必要改动。

## 状态与数据流保护

- 对 `state.json` 的读写检查并发访问、原子性、默认字段补全和异常恢复，避免部分写入或竞态覆盖。
- 对代理和浏览器子进程检查启动失败、端口竞争、重复启动、异常退出及关闭时的状态同步。
- 对 SOCKS5/HTTP 转发检查短读、超时、半关闭、错误响应、流量计数和日志收尾。
- 对下载与解压检查 URL/资产选择、路径穿越、临时目录清理、可执行权限和架构验证。
- 对前端和 Swift 客户端检查请求、响应、错误载荷及可选字段的一致性。

## 错误处理原则

- 用户输入错误返回可理解的业务错误，不泄漏不必要的内部细节。
- 网络、文件和子进程异常必须收敛到已有日志或 API 错误通道，不能留下伪运行状态。
- 清理逻辑应具有幂等性；重复停止或关闭不应产生新的错误。
- 不吞掉能够影响正确性的异常；仅在明确可恢复时使用默认值或继续执行。

## 测试与验证

- 使用现有 `unittest` 套件作为 Python 回归基线，并在同一测试体系中加入针对性回归测试。
- 使用 Python 编译检查覆盖全部 Python 文件。
- 使用 JavaScript 语法检查和静态接口核对覆盖 `static/app.js`。
- 使用 Shell 语法检查覆盖构建脚本。
- 在本机工具链允许时执行 Swift 类型检查或构建；如果完整 App 构建受签名或外部依赖限制，至少完成可执行的编译级检查并明确记录限制。
- 最终验证必须从干净的测试进程重新运行，不能只依赖单个修复点的局部结果。

## 完成标准

- 所有原有测试与新增回归测试通过。
- 所有可用的语法、类型或构建检查通过；无法执行的检查有具体原因说明。
- 每项代码改动都能对应到已记录的问题，不包含无关重构或格式噪声。
- 已确认的严重和高风险问题全部修复；较低风险但不能安全修复的问题明确记录。
- 最终交付包含修复清单、验证结果、剩余风险及涉及文件。
